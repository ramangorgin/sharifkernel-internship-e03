**Project:** Local LLM — Scaling to 1 Billion+ Parameters  
**Platform:** Debian GNU/Linux 13  
**Inference Engine:** Ollama  
**Target Model:** Qwen2.5-1.5B-Instruct  
**Baseline Model:** Qwen2.5-0.5B-Instruct  
**Implementation Type:** Local Model Deployment, Configuration and Benchmarking

---

## 1. Introduction

### 1.1. Project Background

The objective of this project was to develop and improve a locally running Large Language Model (LLM), reaching the requirement of at least one billion parameters.

The previous implementation involved installing Ollama and running a relatively small language model locally.

For this iteration, the objective was to upgrade the existing implementation by selecting a larger model, configuring its execution environment, and evaluating its performance.

### 1.2. Interpretation of the Assignment

The assignment, translated as "Enhancing the designed language model to reach at least one billion parameters", can be interpreted in two ways:

1. Training a language model from scratch with at least one billion trainable parameters.
2. Deploying and configuring an existing open-weight language model with at least one billion parameters.

Considering the available hardware, project scope, and practical requirements, the second approach was selected.

Rather than attempting computationally expensive pretraining, this implementation uses an existing pretrained model and focuses on local deployment, resource optimization, and technical evaluation.

**Important distinction:** The selected model was pretrained by its original developers. This project does not claim to have independently trained or fine-tuned its parameters.

### 1.3. Project Objectives

The primary objectives were:

- Deploy a language model containing more than one billion parameters.
- Run inference locally without relying on a remote AI API.
- Configure the environment for limited hardware resources.
- Explore model quantization and memory optimization.
- Evaluate general knowledge, Persian comprehension, programming, and mathematics.
- Measure inference speed and memory consumption.
- Compare the new model against a smaller baseline model.

### 3.3. Model Quantization

Quantization is a technique that reduces the numerical precision used to represent model weights.

Instead of storing every weight using a higher-precision floating-point representation, quantized models use lower-bit representations.

This reduces:

- Model storage requirements.
- Memory consumption during inference.
- Memory bandwidth requirements.

The Ollama model variants used in this experiment are distributed in compact quantized formats.

The exact quantization type can be inspected using:

```bash
ollama show qwen2.5:1.5b
```

Quantization introduces a potential trade-off between resource efficiency and numerical precision.

## 5. Runtime Optimization

Due to the limited hardware resources, conservative runtime settings were selected for the evaluation.

| Parameter | Configuration |
|---|---|
| CPU Threads | 1 |
| Context Window | 2048 tokens |
| Maximum Generated Tokens | 120 |
| Temperature | 0 |
| Execution Device | CPU |

The context window was deliberately limited to reduce memory consumption.

The model's advertised maximum context length is not necessarily practical on a machine with only 4 GB of RAM.

The temperature was set to zero to reduce randomness and improve the consistency of repeated tests.

## 6. Automated Evaluation System

### 6.1. Evaluation Overview

A Python-based benchmarking script was developed to communicate with Ollama through its local REST API.

The script automatically:

1. Connects to the Ollama API.
2. Checks the availability of the selected models.
3. Sends predefined evaluation prompts.
4. Receives generated responses.
5. Collects inference statistics.
6. Calculates simple heuristic scores.
7. Monitors approximate memory consumption.
8. Generates Markdown and JSON reports.

### 6.2. Evaluation Categories

The evaluation covers the following areas:

| Category | Evaluation Objective |
|---|---|
| General Knowledge | Understanding fundamental technical concepts |
| Persian Comprehension | Understanding and responding to Persian prompts |
| Programming | Explaining Python source code |
| Mathematics | Solving basic mathematical problems |
| Response Speed | Measuring generation speed in tokens per second |
| Memory | Measuring peak Ollama process RSS |
| Context | Retrieving information from a longer input document |

### 6.3. General Knowledge

The model receives a question about DNS and its role in computer networking.

The objective is to evaluate whether the model understands domain names, IP addresses, and name resolution.

### 6.4. Persian Comprehension

A Persian-language prompt asks the model to explain APIs and their applications.

This test evaluates its ability to understand Persian instructions and produce an appropriate Persian response.

### 6.5. Programming

The model receives a short Python program that calculates the average of a list of numbers.

The objective is to evaluate its ability to explain code, identify built-in functions, and understand the program's output.

### 6.6. Mathematics

The model receives a basic discount calculation problem.

The objective is to evaluate arithmetic accuracy and the ability to explain the calculation.

### 6.7. Response Speed

Generation speed is calculated using Ollama's returned statistics:

\[
\text{Tokens per second} =
\frac{\text{Generated Tokens}}
{\text{Generation Duration in Seconds}}
\]

The reported value represents generation throughput, not the time required to load the model.

### 6.8. Memory Consumption

The Python evaluation tool uses `psutil` to periodically sample the Resident Set Size (RSS) of Ollama-related processes.

The highest sampled value is reported as approximate peak Ollama process memory consumption.

This measurement may include shared-memory double counting and should not be interpreted as an exact measurement of physical RAM usage.

### 6.9. Context Handling

A synthetic technical document containing unique project information is supplied to the model.

The model is then asked to retrieve five specific facts.

This test evaluates whether the model can retain and retrieve information from a longer input.

### 6.10. Scoring Methodology

The evaluation script uses keyword-based scoring for general knowledge, Persian comprehension, and programming.

Mathematics and context retrieval also include exact-answer checks.

These scores are heuristic indicators rather than standardized language-model benchmarks or comprehensive semantic assessments.

Generated answers should therefore also be reviewed manually.

### 3. Measurement Notes

- Generation speed is calculated using Ollama's `eval_count / eval_duration` statistics.
- Request latency includes API request overhead and generation time.

## 9. Limitations

Several limitations should be considered:

1. The model was deployed from pretrained weights rather than trained from scratch.
2. CPU-based inference on a single-core Celeron processor limits generation speed.
3. The available physical RAM restricts practical context sizes.
4. Quantization may affect numerical precision and response quality.
5. The evaluation dataset is small and designed for demonstration rather than comprehensive benchmarking.
6. Keyword-based scoring cannot fully evaluate semantic correctness.
7. Memory monitoring provides approximate process-level measurements rather than exact hardware memory attribution.

---

## 10. Conclusion

This project demonstrates the deployment and evaluation of a language model exceeding one billion parameters on a resource-constrained Debian 13 environment.

By using Ollama, it was possible to execute a quantized pretrained model locally without requiring a dedicated GPU or a remote inference API.

A smaller model from the same family was also deployed as a baseline for comparative evaluation.

The automated evaluation system measures several practical aspects of local language-model execution, including response quality indicators, inference speed, memory consumption, and context retrieval.

The project also demonstrates that model size, quantization, computational resources, and inference configuration are important factors in deploying language models on limited hardware.

Although this implementation does not involve pretraining a model from scratch, it provides a practical foundation for further experimentation with local language models, fine-tuning, and model optimization.
